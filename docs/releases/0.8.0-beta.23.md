# 0.8.0-beta.23 — Legacy configuration removal

This release upgrades the integration's configuration entry from version 1 to
version 2. It imports useful current settings once and deletes obsolete keys,
duplicate field representations, and the legacy archive. Subsequent starts and
saves use only the current configuration format.

- EV phase count and efficiency are recovered from the old archive when an
  explicit current value is absent. Explicit current values take precedence.
- Device power/current fields and saved room associations move into their
  current fields. Device identities and setup for devices excluded from the
  plan remain intact.
- Missing reviewed limits and ambiguous old EV observations are reported as
  setup gaps rather than guessed. Review Configuration diagnostics →
  Configuration upgrade for the field-name report.
- No new execution permissions are enabled. The controller's handover journal,
  recorder history, and SHS server history are unchanged.

**Earlier builds cannot load a version-2 entry.** Downgrading the integration
after this upgrade will not undo the migration. Fixes will move forward on the
current schema; the deleted legacy values are not retained by the integration.

The migration uses the [Home Assistant config-entry migration mechanism](https://developers.home-assistant.io/docs/core/integration/config_flow/).

Validation: 304 Python tests, the frontend save test, and Python compilation.
These are automated local checks; deployment and a live HA restart are separate.
