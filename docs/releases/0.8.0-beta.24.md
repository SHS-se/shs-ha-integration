# 0.8.0-beta.24 — Current configuration consolidation

Configuration entry version 3 stores each room's temperature source once, with
heaters referencing that room by its existing Home Assistant area ID. Device
keys, inactive device setup, history identities, and execution permissions are
retained. Shared room edits update the other heater cards while preserving
unrelated unsaved edits.

The panel and public save endpoints now use one field catalog and pure validation
layer. General saves send only changed public fields. Defaults are resolved at
read time; internal scheduling settings and derived records cannot be submitted
through the general settings interface. Invalid ranges, entity shapes, and
incomplete enabled controller setup produce explicit save errors.

An upgrade with different saved temperature sources for the same room fails
before committing any configuration. Select one source for those heaters in the
existing version and retry. No source is silently selected. The upgrade report
lists migrated and removed field names.

**Earlier builds cannot load a version-3 entry.** Migration runs once, with no
runtime legacy lookup. Controller ownership journals and measurement history
are untouched. No new controller is enabled by this release.

Validation: 311 Python tests, three frontend save tests, compilation, and diff
checks. This release has been prepared locally; live HA deployment and restart
verification have not been performed. The four-page redesign follows in Phase 3.
